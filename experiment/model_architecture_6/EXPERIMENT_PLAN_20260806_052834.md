## 1. 最终目标与部署边界

目标是从当前可观测点云、机器人状态和 SAPIEN task metadata 预测抓取与操作动作，使机器人抓住目标 link 并将铰链物体打开到目标角度。

允许在模型输入中使用：

- 当前单视角或多视角点云、目标 link mask；
- 当前及历史机器人 qpos/qvel、已执行 command、可观测接触反馈；
- SAPIEN task metadata 提供的目标 link、铰链轴、关节类型、关节范围和开方向。

最终 deployable forward 禁止读取：

- GT affordance、GT grasp、stored future qpath；
- object joint 的真实当前 progress；
- 未来状态、未来动作、轨迹 outcome、测试集标签。

真实目标 link 打开角度仅由 evaluator 用于成功判定和停止。GT/oracle 可用于上限、接口验证和消融，但必须与 deployable 路线分开记录，不能进入最终推理输入。

## 5. 表示、normalizer 与模型输入

### 5.1 Operation 主表示

对 anchor 时刻已执行的最后一条 command `u_t` 和未来 absolute target `y_{t,h}`，模型预测：

```text
delta_{t,h} = y_{t,h} - u_t
y_hat_{t,h} = u_t + delta_hat_{t,h}
```

训练 loss 只在 valid mask 上计算；offline 指标必须在重建后的 absolute command 上报告。ZERO delta 必须严格重建 repeat-last baseline。

每种 action representation 必须有自己的 `A5_TRAIN`-only normalizer。command-delta normalizer 由 clean sample index 的全部合法 anchor/valid horizon 统计，不能直接复用 absolute-action std。若将来重测 state-start-delta，必须单独生成 state-start-delta normalizer。

### 5.2 共享输入

三种 operation 架构使用完全相同的输入：

- live 1024-point XYZ 和 target-link mask；
- 4-step robot qpos/qvel history；
- last 9D command；
- contact feedback 与 availability mask；
- target joint type、active-joint ordinal、local hinge axis、joint lower/upper、open direction。

ZERO affordance 是独立全零通道，不能与 target mask 混用。第一轮 operation 架构比较固定为 ZERO affordance，affordance 分支失败不得阻塞 operation。

## 6. 评测与决策规则

### 6.1 唯一硬门是实现不变量

以下任一失败都属于 implementation/data contract failure，修复后按相同科学配置重跑，不得作模型负结论：

- 输入、输出、gradient 和 metric 全部 finite；
- command-delta 与 reconstructed absolute loss 数值一致；
- ZERO delta 与 repeat-last 完全一致；
- checkpoint reload 输出一致；
- source/split/hash/mask 精确闭合；
- forbidden-field audit 为零；
- TRAIN/CAL/MECH_DEV/final 读取边界正确；
- 同一 comparison 的模型输入、样本、预算、seed、checkpoint rule 和 evaluator 一致。

数值容差只用于浮点 parity/reload，不用于规定模型必须提升多少。

### 6.2 科学性能不设绝对提升门槛

所有模型都必须与同一样本上的强简单 baseline 比较：

- repeat-last command；
- TRAIN mean delta；
- 可选的线性或小 MLP residual baseline。

报告：valid absolute MAE、endpoint MAE、per-horizon/per-joint error、motion strata、轨迹重放误差、operation progress、wrong-way、contact retention、task success、延迟和资源。

模型选择使用 exact-paired episode difference 和预先声明的 paired bootstrap confidence interval：

- interval 明确支持某 arm 时选择该 arm；
- 区间不能区分时，不宣称性能优胜，依次选择更高 task success、更低 wrong-way、更低 latency/显存、更简单的模型；
- 所有 tie-break 必须在看 MECH_DEV 和 final 之前冻结；
- 不允许事后增加固定百分比、百分点或 loss 倍数门槛。

固定批量的目标是确认实现与可学习性，不要求某个预先猜测的绝对 MAE。若模型不优于 baseline，保留为该架构/表示/配置的 scoped negative，继续其他独立 arm。

## 7. 资源与并行策略

每类新 workload 首次运行前做短 resource pilot，只读 TRAIN 或 synthetic/fixed batch：

1. CPU/materialization 从低 worker 数开始逐步增加，记录吞吐、CPU、内存和 I/O wait；吞吐不再增加或存储成为瓶颈时停止扩展。
2. GPU 从可运行的 batch/microbatch 开始逐步增加，记录 samples/s、显存和稳定性；接近显存上限或吞吐不再增加时冻结配置。
3. 独立模型 arm 和 seed 优先分配到不同 GPU 并行；`O100C/O110C/O120C` 没有科学依赖，禁止人为串行。
4. 资源参数只影响吞吐，不能改变 effective sample exposure、优化步数、数据顺序、loss 或 checkpoint rule。
5. GPUALIVE 只在分析、CPU 工作或循环空闲时保持 GPU 活跃；真实 GPU launch 前必须由 `set_agent_state.py --state launching --resource-mode gpu` 同步停止。GPUALIVE 不是实验进度或完成证据。

### Phase 1：Operation 架构比较

三支使用同一 command-delta、DYN64、输入、normalizer、训练预算、seed 集和 checkpoint rule：

| Run | Decoder | 实现来源 | 依赖 |
|---|---|---|---|
| `A6-O100C` | MLP chunk decoder | `OperationMLPAbsolute` + O200F delta/reconstruction | D021C,D030C |
| `A6-O110C` | parallel learned-query decoder | O020S 网络结构 + command-delta target | D021C,D030C |
| `A6-O120C` | causal decoder | O030S 网络结构 + command-delta target；train/eval 均报告 autoregressive | D021C,D030C |

执行规则：

- 首轮 matched 配置冻结为 hidden dimension 256、dropout 0.1、AdamW、learning rate `1e-4`、weight decay `1e-6`、valid-mask normalized L1、effective batch 64、6,000 optimizer steps、seed `20260806`。模型参数量和实际 microbatch 必须报告；microbatch 可因显存调整，但 effective batch/sample exposure 不变。
- 先做 fixed64 overfit/sanity，随后立刻进入同一 DYN64 screen；fixed64 不产生全局停止。fixed64 可复用 O200F 的已通过 MLP 结果，parallel/causal 使用同一配置补齐。
- 三支独立并行，不能用前一支结果决定后一支是否运行。
- 每支都保存 last checkpoint；DYN64 统一用 A5_CAL offline metric 冻结一个 checkpoint rule。不得为不同 decoder 使用不同 early-stop 规则，也不得挑 best seed。
- 先做 offline same-sample baseline comparison，再做 predicted-command replay，最后做 operation-only live closed loop。
- 如果 causal teacher-forcing 与 autoregressive 差距大，只否定当前 causal decoding，不影响 MLP/parallel。

### Phase 2：Operation 训练策略与正式选择

在 Phase 1 保留下来的 arm 上逐项做单变量实验：

1. raw-uniform 与 motion-balanced sampling；
2. endpoint weighting；
3. scheduled sampling，仅当 offline/replay 好而 live rollout 明显退化时触发；
4. ZERO/PRED/GT affordance intervention，先测 frozen checkpoint sensitivity，再做 matched-train utility。

不得自动加入 Diffusion、Cartesian/IK、DAgger 或更大 backbone。只有现有 evidence 明确指向对应瓶颈，并发布新的 planning revision 后才能新增。

Operation 正式阶段对候选做多 seed A5_TRAIN 训练、A5_CAL exact-paired 选择和 result-to-claim audit。此时只冻结 operation module，不读取 MECH_DEV/final。

### Phase 3：抓取两种方案的公平比较

抓取必须比较用户指定的两条路线：

| 路线 | 模型输出 | 在线执行 | 核心要求 |
|---|---|---|---|
| `G-TRAJ` | 从当前 observation 直接预测完整抓取 qpath | 仅重采样后交给同一 qpath executor，不允许 planner 修正 | 学习路径本身 |
| `G-QPOSE` | 只预测 open terminal grasp qpose/candidate set | 在线 planner 从当前 robot state 规划到预测 qpose，再走同一 executor | 禁止读取 stored pregrasp/qpath |

公平合同冻结为：每个 observation group 只能聚合同一 initial robot/object/base/camera state 和同一 target link；最多保留 `K=4` 个 trajectory-specific teacher，少于 K 时使用 valid/presence mask，禁止复制 label 填充。每条 teacher path 在保留首尾点的前提下按 7D joint-space 累计弧长确定性重采样到 `L=64`。

`G-TRAJ` 输出相对当前 arm qpos 的 `K x L x 7` path；`G-QPOSE` 输出相对当前 arm qpos 的 `K x 7` open terminal qpose。两者都输出 K 个 presence logit，使用 group 内 Hungarian matching；presence 表示数据 proposal slot 是否存在，不是 outcome confidence。两者共享 observation encoder、ZERO affordance、K、训练 groups、seed、optimizer、sample exposure、close/settle、path executor 和 frozen operation winner。

`G-TRAJ` geometry loss 固定为 `mean_waypoint_L1 + endpoint_L1 + 0.1 * first_difference_L1`；`G-QPOSE` 固定为 `terminal_L1`；两者都加 `0.1 * presence_BCE`。各 loss 只在 valid label 上归一化，不能读取 contact/task outcome。首轮 fixed-batch 均使用 6,000 matched optimizer steps；参数量无法接近时必须报告差异、planner time 和端到端 latency。

GT-QPOSE 和 learned QPOSE consumer 都只能执行 current-state -> predicted/GT terminal qpose 的 single-segment online joint planner；必须用 field/AST audit 证明没有读取 stored pregrasp 或 stored qpath。两条路线最后都执行相同 L64 qpath scheduler、close 和 settle 逻辑。

顺序：

1. `A6-G000C`：冻结 qpath、`q_path_terminal_open`、`q_operation_start_closed` 三状态标签和 K-candidate set；严禁把 closed operation state 当 qpose teacher。
2. `A6-G005C`：GT-TRAJ 与 GT-QPOSE+online planner 的接口上限 exact-paired 比较。它验证 consumer 是否可执行，不选择最终 deployable 模型。
3. `A6-G010C/G020C`：两条 learned route 的 fixed-batch learnability；共享 encoder、candidate 数、样本、seed 和 exposure。
4. `A6-G100C/G110C`：DYN64 offline 与物理 screen，分别报告 planner coverage、reach、contact、retention、transition-to-operation 和 task success。
5. `A6-G120C`：按 paired evidence 和工程 tie-break 冻结抓取表示；若不可区分，优先选择更简单、更低 latency、失败模式更可观测的路线。

旧 Architecture 2/4 的 stored qpath、GT SE(3) 和 candidate planner 结果只作为接口与代码证据，不得冒充这里的 target-qpose-only 比较结果。

### Phase 4：Affordance 如何介入

Affordance 有独立主线，不阻塞 ZERO operation/grasp：

1. `A6-A010C`：clean TRAIN fixed8 随机初始化 fit，验证点级 label、mask、reload 和 consumer shape。
2. `A6-A020C`：复用 Stage-1 `R100_uniform_updated` 的 uniform-combined data/optimizer/epoch protocol，在 clean A5_TRAIN 上以 seeds `20260806/20260807/20260808` 从随机初始化完整训练；只用 A5_CAL 冻结 checkpoint rule，不挑 best seed。
3. `A6-A030C`：冻结 deployable PRED affordance producer，验证 live point alignment 与 deterministic reload。
4. 对 operation 和两条 grasp route 分别做 `ZERO/PRED/GT`：
   - frozen-PRED sensitivity：只替换输入，判断 consumer 是否真的使用 affordance；
   - matched-train utility：各 condition 独立训练，判断 affordance 是否改善物理任务；
   - GT 只给上限，不参与最终系统。

只有 point metric 提升而下游 reach/contact/task 不改善时，结论应是“当前 consumer 没有把空间信号转成动作收益”，不能写成 affordance 模型失败。

### Phase 5：抓取、Operation 与 Affordance 联合优化

完成 operation winner、grasp winner 和 PRED affordance 冻结后：

1. `A6-J000C`：组合 frozen modules，得到 deployable pipeline baseline。
2. `A6-J100C`：shared encoder 的 supervised joint training，与 frozen pipeline 做 exact-paired 比较。
3. 分别报告 operation-only、grasp-only 和完整 task，避免完整任务变化掩盖某一阶段退化。
4. affordance auxiliary loss 只有在 Phase 4 显示下游 utility 或明确 headroom 时加入；否则保持独立 producer。
5. task fine-tune/DAgger 仅在 supervised joint 的错误归因明确且有合法 TRAIN-only teacher 时另发 revision。

联合模型没有预设必须提升多少；若 paired evidence 不能支持收益，则保留 frozen pipeline，不能用任意百分点门槛宣告失败。

### Phase 6：开发集与最终测试

只有一个完整系统和全部 checkpoint/selector/stop rule 冻结后才能执行：

1. `A6-J210C`：读取一次 `A5_MECH_DEV`，在 frozen pipeline 与 joint candidate 之间做最终系统选择。
2. `A6-J220C`：deployment audit，确认无 oracle field、hash/config 完整、evaluator-only angle stop。
3. `A6-F000C`：唯一系统做 SAME_TEST。
4. `A6-F010C`：同一系统做 `A5_TARGET_TEST`。
5. `A6-F020C`：汇总 paired CI、stage failure strata、资源与适用范围；final 后禁止再训练。

## 9. Failure classification 与防偏离规则

### 9.1 分类

- `implementation_failure`：crash、shape、normalizer、parity、reload、错误字段或 runner/config drift。
- `data_contract_failure`：split/membership/hash/mask/lineage 不闭合。
- `training_fit_negative`：实现有效，但该模型/表示/配置在同一样本上不优于 baseline。
- `closed_loop_negative`：offline/replay 有效，但物理执行没有收益。
- `scientific_negative`：多个有效、受控、独立 arm 都不能支持预先声明的 claim；范围必须写清。

前两类修复后重跑同一科学配置。后三类只能否定本 run 的明确范围，不能自动结束整个 Architecture 6。

### 9.2 明确禁止

- 禁止再运行 `A6-A000RR/A000RRR/A000RRRR` 或任何 dirty-row recovery。
- 禁止重新寻找 oracle controller、重新证明 replay_quality_gate 或重做 collection trajectory reconstruction。
- 禁止把 independent arms 串行化，或因 affordance 未完成阻塞 ZERO operation。
- 禁止用 stale `active_contract`、旧 planning revision、旧 termination 或旧 dashboard 启动任务。
- 禁止把任意固定性能提升比例、百分点或从初始化下降倍数重新写成硬门。
- 禁止一个 arm 的 negative 自动标记全局 `unsuccessful`。
- 禁止读 heldout 后修改 model、loss、normalizer、selector、stop rule 或 tie-break。

- `run_state.json`、`queue_state.json`、`summary.json`；
- `run_manifest.json`、`training_config.json`、`command.json`；

- forbidden-feature audit、resource pilot/ref、reload/parity checks；
