## 1. 最终目标与部署边界

目标是从当前可观测点云、机器人状态和 SAPIEN task metadata 预测抓取与操作动作，使机器人抓住目标 link 并将铰链物体打开到目标角度。

允许在模型输入中使用：

- 当前单视角或多视角点云、目标 link mask；
- 当前及历史机器人 qpos/qvel、已执行 command、可观测接触反馈；
- SAPIEN task metadata 提供的目标 link、铰链轴、关节类型、关节范围和开方向。

最终 deployable forward 禁止读取：

- GT affordance、GT grasp、stored future qpath；
- object joint 的真实当前 progress；
- 未来状态、未来动作、轨迹 outcome、测试集标签。

真实目标 link 打开角度仅由 evaluator 用于成功判定和停止。GT/oracle 可用于上限、接口验证和消融，但必须与 deployable 路线分开记录，不能进入最终推理输入。

## 5. 表示、normalizer 与模型输入

### 5.1 Operation 主表示

对 anchor 时刻已执行的最后一条 command `u_t` 和未来 absolute target `y_{t,h}`，模型预测：

```text
delta_{t,h} = y_{t,h} - u_t
y_hat_{t,h} = u_t + delta_hat_{t,h}
```

训练 loss 只在 valid mask 上计算；offline 指标必须在重建后的 absolute command 上报告。ZERO delta 必须严格重建 repeat-last baseline。

每种 action representation 必须有自己的 `A5_TRAIN`-only normalizer。command-delta normalizer 由 clean sample index 的全部合法 anchor/valid horizon 统计，不能直接复用 absolute-action std。若将来重测 state-start-delta，必须单独生成 state-start-delta normalizer。

### 5.2 共享输入

三种 operation 架构使用完全相同的输入：

- live 1024-point XYZ 和 target-link mask；
- 4-step robot qpos/qvel history；
- last 9D command；
- 第一轮 deployable baseline 将 33D contact telemetry 与 availability 共 34 维严格置零；数据集 `contact_feedback` 包含 object progress 和 controller 内部量，禁止进入 baseline 模型。后续 contact 消融必须另行定义仅由当前可测量构成的传感器 schema；
- target joint type、active-joint ordinal、local hinge axis、joint lower/upper、open direction。

ZERO affordance 是独立全零通道，不能与 target mask 混用。第一轮 operation 架构比较固定为 ZERO affordance，affordance 分支失败不得阻塞 operation。

训练/离线诊断必须记录 `observation_source`：`recorded_current_observation` 或 `live_sapiens_observation`。recorded observation 可用于 held-out supervised metric，但只有相同无 oracle schema 的 live observation 能支持部署结论。

## 6. 评测与决策规则

### 6.1 唯一硬门是实现不变量

以下任一失败都属于 implementation/data contract failure，修复后按相同科学配置重跑，不得作模型负结论：

- 输入、输出、gradient 和 metric 全部 finite；
- command-delta 与 reconstructed absolute loss 数值一致；
- ZERO delta 与 repeat-last 完全一致；
- checkpoint reload 输出一致；
- source/split/hash/mask 精确闭合；
- forbidden-field audit 为零；
- TRAIN/CAL/MECH_DEV/final 读取边界正确；
- 同一 comparison 的模型输入、样本、预算、seed、checkpoint rule 和 evaluator 一致。

数值容差只用于浮点 parity/reload，不用于规定模型必须提升多少。

### 6.2 科学性能不设绝对提升门槛

所有模型都必须与同一样本上的强简单 baseline 比较：

- repeat-last command；
- TRAIN mean delta；
- 可选的线性或小 MLP residual baseline。

报告：valid absolute MAE、endpoint MAE、per-horizon/per-joint error、motion strata、轨迹重放误差、operation progress、wrong-way、contact retention、task success、延迟和资源。

模型选择使用 exact-paired episode difference 和预先声明的 paired bootstrap confidence interval：

- interval 明确支持某 arm 时选择该 arm；
- 区间不能区分时，不宣称性能优胜，依次选择更高 task success、更低 wrong-way、更低 latency/显存、更简单的模型；
- 所有 tie-break 必须在看 MECH_DEV 和 final 之前冻结；
- 不允许事后增加固定百分比、百分点或 loss 倍数门槛。

固定批量的目标是确认实现与可学习性，不要求某个预先猜测的绝对 MAE。若模型不优于 baseline，保留为该架构/表示/配置的 scoped negative，继续其他独立 arm。

## 7. 资源与并行策略

每类新 workload 首次运行前做短 resource pilot，只读 TRAIN 或 synthetic/fixed batch：

1. CPU/materialization 从低 worker 数开始逐步增加，记录吞吐、CPU、内存和 I/O wait；吞吐不再增加或存储成为瓶颈时停止扩展。
2. GPU 从可运行的 batch/microbatch 开始逐步增加，记录 samples/s、显存和稳定性；接近显存上限或吞吐不再增加时冻结配置。
3. 独立模型 arm 和 seed 优先分配到不同 GPU 并行；`O100C/O110C/O120C` 没有科学依赖，禁止人为串行。
4. 资源参数只影响吞吐，不能改变 effective sample exposure、优化步数、数据顺序、loss 或 checkpoint rule。
5. GPUALIVE 只在分析、CPU 工作或循环空闲时保持 GPU 活跃；真实 GPU launch 前必须由 `set_agent_state.py --state launching --resource-mode gpu` 同步停止。GPUALIVE 不是实验进度或完成证据。

### Phase 3：抓取两种方案的公平比较

抓取必须比较用户指定的两条路线：

| 路线 | 模型输出 | 在线执行 | 核心要求 |
|---|---|---|---|
| `G-TRAJ` | 从当前 observation 直接预测完整抓取 qpath | 仅重采样后交给同一 qpath executor，不允许 planner 修正 | 学习路径本身 |
| `G-QPOSE` | 只预测 open terminal grasp qpose/candidate set | 在线 planner 从当前 robot state 规划到预测 qpose，再走同一 executor | 禁止读取 stored pregrasp/qpath |

公平合同冻结为：每个 observation group 只能聚合同一 initial robot/object/base/camera state 和同一 target link；最多保留 `K=4` 个 trajectory-specific teacher，少于 K 时使用 valid/presence mask，禁止复制 label 填充。每条 teacher path 在保留首尾点的前提下按 7D joint-space 累计弧长确定性重采样到 `L=64`。

## 9. Failure classification 与防偏离规则

### 9.1 分类

- `implementation_failure`：crash、shape、normalizer、parity、reload、错误字段或 runner/config drift。
- `data_contract_failure`：split/membership/hash/mask/lineage 不闭合。
- `training_fit_negative`：实现有效，但该模型/表示/配置在同一样本上不优于 baseline。
- `closed_loop_negative`：offline/replay 有效，但物理执行没有收益。
- `scientific_negative`：多个有效、受控、独立 arm 都不能支持预先声明的 claim；范围必须写清。

前两类修复后重跑同一科学配置。后三类只能否定本 run 的明确范围，不能自动结束整个 Architecture 6。

### 9.2 明确禁止

- 禁止再运行 `A6-A000RR/A000RRR/A000RRRR` 或任何 dirty-row recovery。
- 禁止重新寻找 oracle controller、重新证明 replay_quality_gate 或重做 collection trajectory reconstruction。

- 禁止用 stale `active_contract`、旧 planning revision、旧 termination 或旧 dashboard 启动任务。
- 禁止把任意固定性能提升比例、百分点或从初始化下降倍数重新写成硬门。

### 13.4 第二个 live 协议 bug 及证据边界

4. O188 首 arm O127 `2/8` 与 O191 首 arm seed1 `5/8` 都是值得复核的信号，但来自不同 run，不能提前形成 residual 优于 O127 的结论。

### 13.6 O193C 有效结果与 residual 稳定性实验

O193C terminal artifact：`results/a6_o193c_fresh_world_fixed_budget_live8_v1/summary.json`。O127 为 mean progress `0.24232`、task `2/8`；random residual seed1 为 `0.31365 / 5/8`，seed2 为 `0.28965 / 3/8`。两支相对 O127 的 paired mean progress 分别为 `+0.07133 [-0.01491,0.18111]`、`+0.04733 [-0.00608,0.10978]`，aggregate contact 均值也未下降；O127 相对 repeat-last 的 progress 为 `+0.24163 [0.14367,0.33535]`、task `+2`。因此：

1. fresh-world 下存在明确可学习信号，不能再称为“模型没有拟合”；
2. recovery residual 方向有任务收益信号，允许继续优化；
3. seed1/seed2 的 `5/8` 对 `3/8` 说明临界 target 对训练采样顺序敏感，当前不能只挑 seed1 冻结 winner。

O194C 的唯一假设是：O185/O189 对 1024 prefix rows 与 128 recovery rows 都采用有放回随机采样，有限训练中各 row 的实际 exposure 不等；将每个数据段改为逐 epoch 随机排列、无放回覆盖，可在不增加总曝光或模型容量的前提下降低 seed 方差。执行合同：

1. 两个 seed 使用同一 O127、D180 time-aligned 数据、zero-init linear residual、`6000` steps、每 step `32 prefix + 32 recovery`、相同 optimizer/loss/normalizer；只改 sampling mode。
2. prefix 每 32 steps 完整覆盖 1024 rows；recovery 每 4 steps 完整覆盖 128 rows。6000 steps 后 prefix 每 row exposure 只能相差 1，recovery 每 row必须完全相同；保存 exposure min/max 与 sampler test。
3. O195C 在 frozen A5_CAL 同时报 baseline、旧 random seed1、两个 balanced seeds；只要实现/finite/checkpoint 合同通过就进入 O196C，不能因为 CAL MAE 小幅变化取消 live。
4. O196C 的四个 arm 全部现场 fresh-world 执行。主要判断是两个 balanced seeds 相对 baseline/random seed1 的 per-target progress/contact/task 及 balanced seed gap；不设绝对提升比例。若两支 balanced seed 都保持 residual 的 task/progress 方向且 seed gap 收窄，则采用 balanced sampler；否则保留 O185 random seed1 为当前候选并转向其他可部署结构，不继续无界 sampler 调参。

O196C terminal artifact：`results/a6_o196c_balanced_recovery_residual_live8_v1/summary.json`。balanced seed1/2 均为 task `3/8`，mean progress `0.27639/0.26134`，相对 random seed1 的 paired progress 为 `-0.03726 [-0.09568,0.00437]`、`-0.05231 [-0.13434,0.00358]`，task 均为 `-2`；balanced seed gap 虽缩小，但性能一起下降。该 sampler 是有效实现下的 scoped negative，禁止继续调 epoch/batch 参数。

### 13.7 O197C--O199C residual weight average

O185/O189 使用完全相同且冻结的 O127 baseline，唯一可训练参数是线性 `recovery_head`。因此对两个 residual head 的 weight/bias 做 50/50 平均，数学上等价于对两模型 normalized command-delta 输出求平均，同时仍只需一次 encoder/decoder/head forward。该实验直接测试能否保留 seed1 收益并降低 seed-specific correction，不是 ensemble 算力扩展，也不使用 oracle。

1. O197C 必须逐 tensor 证明两个 checkpoint 的 `baseline.*` 完全相同；只平均 `recovery_head.weight/bias`。在 frozen D042C fixed batch 上验证 merged output 与两 seed output mean 的 max error，允许的数值误差只用于实现正确性，不作为性能 gate。
2. O198C 同时评估 baseline、random seed1、random seed2、weight average；CAL 仅确认 checkpoint/consumer/finite，不能提前取消 O199C。
3. O199C 四 arm 全部使用 independent world、650 calls、K8 和 opening-angle stop。报告 weight-average 相对 baseline/seed1/seed2 的 paired progress/contact/task。
4. 这是 residual 稳定性方向的最后一个 focused 变体。若 weight average 未超过或稳定匹配 seed1，则停止 sampler/seed 融合调参，保留 O185 seed1 作为当前 operation 候选，并将下一 revision 转向新的可部署观测/控制结构或按全局计划进入抓取比较。

O199C terminal artifact：`results/a6_o199c_recovery_residual_weight_average_live8_v1/summary.json`。weight average mean progress/task 为 `0.26895 / 4/8`；相对 O127 为 `+0.02663 [-0.02573,0.08683]`、task `+2`，相对 seed1 为 `-0.04470 [-0.13212,0.00315]`、task `-1`，相对 seed2 为 `-0.02070 [-0.04660,-0.00200]`、task `+1`。它没有超过 seed1，且 progress 明确低于 seed2，故不选择。
